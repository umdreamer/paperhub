# PaperHub 0.1.0 资料规则与数据模型

本文件把[需求讨论记录](需求方案.md)中已确认的规则转为实施依据。0.1.0 的第一步只建立本地索引和人工预览；文件移动、Zotero 写入及旧库批量改名须在各自 Issue 中实现和验收。

## 1. 条目与附件

一个 `work` 表示一项可引用的科研资料，使用创建后不变的 UUID。`kind` 取 `paper`、`book`、`presentation`、`webpage`、`video` 或 `other`。条目含题名、作者或机构、年份或发布日期、来源、DOI、URL、访问日期、主题分类及各字段的来源和核验状态。缺失字段保持空值，不从文件名猜测作者、DOI 或出版信息。网页即使没有本地快照也可作为条目；URL 和访问日期须记录。

一个 `asset` 表示一个本地文件，使用创建后不变的 UUID。它记录当前路径、原路径、文件大小、MD5、SHA-256、修改时间、格式、核验状态。单个文件可关联多个 `work`，但只在磁盘保留一份实体。`work_asset` 关系含 `role`，可取 `main`、`supporting_info`、`supplement`、`slides`、`video`、`snapshot` 或 `other`，另存排序号和备注。独立演讲可有自己的 `work`；同一 Slides 文件也可作为某篇论文的附件。引用导出以 `work` 为单位，附件不会自动产生重复引用条目。

`zotero_link` 保存 PaperHub `work_id`、Zotero 库标识、条目键和附件键。Zotero 键与 BibTeX 键是不同标识；不能互相替代。`scan_event` 保存发现、校验、匹配和导出状态及错误；任务重试应使用稳定事件 ID，避免重复创建条目。

## 2. SQLite 与更新顺序

SQLite 是唯一可写的主索引。按 `work`、`asset`、`work_asset`、`zotero_link`、`scan_event`、`field_provenance` 和 `export_revision` 分表。外键启用，路径、Zotero 库加条目键、事件 ID 建唯一约束；摘要建立普通索引，不把摘要设为唯一，因为同一内容可保留多个来源路径。正文抽取结果使用 FTS5 全文索引，抽取失败只记录错误，不阻断元数据索引。

监听器接收事件后等待文件稳定，再将路径、大小、时间戳写入待处理队列。扫描器重新读取文件并计算摘要，在同一事务中更新资产和关系；启动及定时补扫负责恢复漏掉的事件。每次输出 HTML、Excel、BibTeX、JSON 均读取同一数据库快照；先生成和校验新文件，再保存旧版本并替换正式输出。失败时保留上一次完整输出，记录失败的修订号。

## 3. 文件核验、重复和命名

完全相同候选须满足文件字节数、MD5 和 SHA-256 均一致；任何合并、替换路径或复用实体前，再逐字节核对。仅题名相同不是重复证据。软件不自动删除文件，也不以重复为由覆盖文件。PDF 另验文件头、结构和可读首页；电子书、PPT、网页快照和视频由各自格式适配器核验。无法读取的资料留在原处并进入复核队列。

现有论文主文件保持 `年份-刊会-题名.pdf`，位于 `PaperHub/一级主题/二级主题/`。附件放在同一目录，使用 `主文件名--SI-01.pdf`、`主文件名--Slides-01.pptx` 等角色后缀；序号从 01 起，按角色独立编号。文件名只替换目标文件系统不允许的字符。主文件名中的刊会或题名未知时，不自动组成看似完整的名称，而进入人工复核。非论文资料使用经确认的类型专属命名规则；0.1.0 不自动改名旧库中的电子书、网页或演讲资料。

路径冲突时按顺序处理：同一路径且逐字节相同，保留原件并建立关系；同一路径而内容不同，停止写入，产生带两方摘要的冲突任务；同题但不同版本，保留两个资产并由用户确认主次。数据库中的 UUID 是关联依据，文件名、DOI 和题名都不是唯一主键。旧版本和原文件在覆盖或迁移前保留；归档目录不得自动清理。

## 4. Zotero 边界

同机共享以 PaperHub 文件作为 Zotero 链接附件的目标。Zotero 存储附件导入 PaperHub 时须复制并核验，保留 Zotero 原件。条目匹配优先使用已记录的 Zotero 键，其次 DOI，再按题名、作者和年份给出候选；多候选不自动合并。Zotero 接口暂不可用时，本地索引仍可工作，同步任务留在队列中重试。对 Zotero 的写入只走其正式接口，不直接改 Zotero SQLite 文件。

## 5. 0.1.0 的验收边界

本版本首先交付可读的 SQLite 索引、文件盘点与冲突预览；它必须在测试目录中覆盖论文、电子书、PPT、网页快照、视频及同一论文的多个附件。每个索引结果能追溯路径和两个摘要，重启补扫不产生重复条目。只有完成单独 Issue 的实测后，才可声称自动命名、Zotero 双向写入或现有 HTML 等输出已投入使用。
